This document records the reproducible state observed before Phase 1 build-system changes. It is evidence, not a claim that the current compiler or runtime is production-safe.

## Parallel Build Regression Evidence

Command:

```powershell
cmake --build out/baseline-vs2022 --config Debug --target dbp_tests --parallel 8 -- /m:8 /clp:ErrorsOnly
```

Result: failed with exit code `1`.

MSVC reported `C1041` for concurrent writes to:

```text
out/baseline-vs2022/bin/Debug/dbp_compiler_lib.pdb
```

The error occurred across many translation units in `dbp_compiler_lib` and explicitly recommends `/FS`. A follow-up serialized invocation remained blocked because the failed compiler processes/PDB server retained the same PDB. The baseline test executable was therefore not regenerated inside this isolated worktree before the build-policy fix.

This is the RED regression evidence for target-scoped parallel-PDB handling. The fix must be verified with repeated clean parallel builds, not only with a serialized build.

## CTest Discovery Regression Evidence

Command:

```powershell
ctest --test-dir out/baseline-vs2022 -C Debug --show-only
```

Result:

```text
Total Tests: 0
```

CTest returned success despite discovering no tests. The root CMake project creates `dbp_tests` but does not enable/register tests. This is the RED regression evidence for CTest integration.

## Baseline Limitations

- Clean parallel build fails.
- CTest discovers zero tests.
- The isolated clean test executable has not yet been produced.
- DirectX SDK discovery is environment/path dependent.
- Dependencies are downloaded during configure and are not reproducibly pinned.
- Build flags are directory-global and leak legacy settings into third-party code.
- No shared CMake presets or Windows CI workflow exist.
- FPS Creator Classic compatibility has not yet been executed or measured.
- This baseline does not validate Unicode completeness, x64, CLI correctness, VFS safety, AST parity, runtime plugins, or rendering.
