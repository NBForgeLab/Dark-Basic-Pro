# Phase 3: Automated Testing Environment

## 🎯 Goal
Build a testing environment to automatically verify the correctness of the compiler and engine. Automated unit and integration tests create a "safety net" that prevents regressions when refactoring code or adding new compiler features.

---

## 🛠️ Recommended Framework: Google Test (GTest)
We suggest integrating **Google Test** into the CMake build system:
* **Why GTest?**: It is the industry standard for C++, provides excellent IDE integration (like Visual Studio's Test Explorer), and separates test logic from the main application binary.

---

## 🏗️ CMake Configuration for Testing

Enable unit tests conditionally in the `CMakeLists.txt` configuration:

```cmake
option(BUILD_TESTS "Build unit tests" ON)

if(BUILD_TESTS)
    enable_testing()
    
    # Automatically download Google Test using FetchContent
    include(FetchContent)
    FetchContent_Declare(
        googletest
        URL https://github.com/google/googletest/archive/release-1.11.0.zip
    )
    FetchContent_MakeAvailable(googletest)
    
    # Create the test executable target
    add_executable(dbp_tests
        tests/test_main.cpp
        tests/test_vartable.cpp
        tests/test_parser.cpp
    )
    
    # Link with GTest and compiler libraries
    target_link_libraries(dbp_tests PRIVATE gtest_main dbp_compiler_lib)
    
    # Register the test suite
    add_test(NAME dbp_unit_tests COMMAND dbp_tests)
endif()
```

## 💻 Writing Initial Unit Tests

Create a folder named `tests` and write unit tests for isolated classes:

### Testing the Variable Table (`test_vartable.cpp`)
```cpp
#include <gtest/gtest.h>
#include "VarTable.h"
#include "CompilerContext.h"

TEST(VarTableTest, AddAndRetrieveVariables) {
    CompilerContext ctx;
    CVarTable* varTable = ctx.GetVarTable();
    
    // Add variables
    varTable->AddVariable("myIntegerVar", 1); // 1 = Integer type
    varTable->AddVariable("myStringVar", 2);   // 2 = String type
    
    // Assert correct lookup and counts
    EXPECT_EQ(varTable->GetCount(), 2);
    EXPECT_TRUE(varTable->Exists("myIntegerVar"));
    EXPECT_TRUE(varTable->Exists("myStringVar"));
    EXPECT_FALSE(varTable->Exists("nonExistentVar"));
}
```

### Integration Compilation Tests
Automate a test script that compiles a small DarkBasic snippet (e.g., variable assignment and addition) and checks if the generated byte block runs correctly:
```basic
a = 10
b = 20
c = a + b
```
The test verifies that the compiler generates output without crashing, producing a correct `EXEBlock` signature.

---

## 🚀 Benefits
* **Refactoring Confidence**: Safely change core memory implementations or internal structures knowing that any regression will be flagged immediately by running the tests.
* **Living Documentation**: Tests act as exact examples of how the compiler's APIs should be called and used.
