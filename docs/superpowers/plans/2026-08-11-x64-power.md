# Plan — Wave 17: Internal Power instruction (exp/log)

## Mission

Replace the `PowerLLL` (int) and `PowerFFF` (float) dbprocore.dll calls with
an emitter-built `exp(y·log(x))` sequence using msvcrt `exp`/`log` — TDD.

## Context

The DLL Power functions are thin CRT `pow` wrappers (`(int)pow((long
double)a,(long double)b)` / `(float)pow(a,b)`), and `pow(x,y) = exp(y·log(x))`
for positive x. The emitter can own this decomposition: widen operands to
double, call `log`, `MULSD`, call `exp`, narrow to the target type. The two
CRT calls go through the existing command table (msvcrt.dll is a guaranteed
system DLL; `exp`/`log` are undecorated exports) with fully-balanced
SUB/ADD frames mirroring `EmitX64CallFrame`'s alignment math — no value-stack
involvement.

## TDD discoveries

1. **`BuildTask::Power = 101` already existed** (legacy dead enum entry) —
   reused it instead of adding a new ID; the new registration simply points
   `PowerLLL`/`PowerFFF` at it.
2. **`ASMTask::Power = 101` was also pre-existing and unused** — repurposed
   with the new emission block; the `TaskPowerValue` characterization test
   stayed green untouched.
3. **No new opcodes needed**: `MOVSD XMM1,XMM0` + reload handles the y
   operand; every other instruction (MOVSD mem forms, MULSD, CVT* family)
   came from waves 8/15/16.
4. **CStr::AddText takes LPSTR** — the helper builds the command table row
   with a `const_cast` (matches the legacy `WriteASMCall` convention of a
   `"["` DLL marker + `","` command marker stripped by AddCommandToTable).
