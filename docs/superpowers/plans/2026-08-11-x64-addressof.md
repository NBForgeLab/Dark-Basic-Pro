# Wave 14 — `&var` (Address-Of) as a Full 8-Byte Address — Plan

Date: 2026-08-11

## Goal

Make `&variable` in user code produce a full 8-byte address on x64 instead of
a truncated 4-byte DWORD, consistent with the 8-byte array interface built in
waves 6/7/8b.

## Steps

- [x] Design doc: `docs/superpowers/specs/2026-08-11-x64-addressof-design.md`
- [x] RED: `tests/test_x64_addressof.cpp` — task-level byte tests asserting the
      `&b` load reads 8 bytes (`48 8B 88` / `MOV RCX,[RAX+0]`, `48 8B C1`),
      the int64 target stores `MOV [@a],RAX` with **no** cast DLL `CALL`,
      the int target stores 4 bytes with no cast DLL, and no `8B 88`/`8B C1`
      (4-byte truncation) appears in the address-of path.
- [x] Implement:
  - `MathOp.cpp` `DoValueSingleVariable`: `&`-prefixed results → type 107
    (global + local branches).
  - `TaskEmitter.cpp` `DetermineASMCallForREL` + `DetermineASMCall`: type 107
    → 8-byte (REX.W) opcodes on x64.
  - `Parameter.cpp` `CastAllParametersToInstruction`: 107 → no cast to
    integer-family targets (1/4/5/6/7/9).
- [x] GREEN: run the wave-14 tests + full suite (1050/0/1 skip).
- [x] Full build + ctest (100%) + docs/17 entry + plan checkboxes; delete the
      diagnostic probe `tests/test_x64_addressof_probe.cpp`.

## Verification

- `a = &b` (int): read 8 bytes, store 4 — truncation is the user's choice.
- `a = &b` (int64): read 8 bytes, store 8 — **no DLL cast call**.
- `a = &b` (dword/byte): read 8 bytes, store at destination width.
- No 4-byte truncating read of the companion value in any address-of path.
- `b(0)` (regular int array element) still reads 4 bytes.
